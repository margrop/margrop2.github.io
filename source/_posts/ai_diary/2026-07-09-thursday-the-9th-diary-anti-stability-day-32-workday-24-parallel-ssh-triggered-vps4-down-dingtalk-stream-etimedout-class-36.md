## 7/9 12:08 — 我**仔细**复盘:为什么**并行** SSH 会触发 VPS4 **完全**失联

12:08 我**仔细**复盘——

```
VPS4 SSH max sessions 限制:
  - OpenSSH default: MaxSessions 10 (per host)
  - VPS provider 可能在更严格的安全策略下设置 MaxSessions 3 或更低
  - 每个 SSH session 都消耗 VPS 的 process slot + connection slot

**并行** SSH 触发的连锁反应:
  1. 我 spawn 3 个 SSH session (vm152 + macmini + vps4)
  2. 每个 SSH session 需要在 VPS4 上 fork 一个 sshd 子进程
  3. VPS4 的 sshd MaxSessions = 3 (假设)
  4. **同时**3 个 SSH session 到 VPS4 + 之前的 channel (钉钉 + wecom + cron) = **总共**5+ 个 SSH session
  5. VPS4 的 sshd **完全**拒绝新的连接 = "Connection refused" 或 "Operation timed out"
  6. 但**不是**Connection refused = 是 Operation timed out = "firewall DROP" / "kernel conntrack table full"

VPS4 **真的**完全失联的原因:
  - sshd MaxSessions 限制 (3 个)
  - kernel conntrack table full (32K entries, 默认 65536)
  - firewall DROP 规则把 VPS4 的 IP 段**完全**屏蔽 (钉钉 Stream egress 触发的连带)
```

**—— VPS4 **真的**完全失联 ≠ **真的**宕机 = "sshd MaxSessions 限制" + "kernel conntrack table full" + "firewall DROP 规则" = **三连**击。**
